# Launch switch (do not apply during review)

These files are ready to deploy when Spike says the site can go public on Friday 13 November 2026 (Pacific/Auckland). Until then, leave the live review banner and basic auth in place.

## Order of operations

1. Upload `config.remarkablemensballet.com.php` and `config.www.remarkablemensballet.com.php` from this folder over the matching files in `site/config/` on the host.
2. Clear `site/cache/` on the host (delete the contents, keep the folder).
3. Confirm in a private window (still with the review login) that the yellow "Reviewer's note" banner is gone from the home page, the Hall of Fame and the 404 page.
4. Confirm `https://remarkablemensballet.com/robots.txt` allows crawling and lists the sitemap, and that `https://remarkablemensballet.com/sitemap.xml` lists the public pages with absolute `https://remarkablemensballet.com/...` URLs.
5. Confirm `http://remarkablemensballet.com` and `https://www.remarkablemensballet.com` 301 to `https://remarkablemensballet.com`.
6. Confirm `/panel` shows a login (or a planned installer step), not a broken public page you did not expect.
7. Then remove basic auth, as below.
8. Immediately open `https://remarkablemensballet.com` in a private window with no password, and check the home page, a profile, a form, and a share preview (absolute `og:image`).
9. Keep a five-minute rollback: put the auth block back if something looks wrong.

## Removing basic auth

On the live server, edit `public_html/.htaccess` and delete only this review-auth block at the top of the file. Do not touch the HTTPS / www redirect rules, the Kirby rewrite rules, or the cPanel php ini directives at the bottom.

```
# Review-phase Basic Auth
AuthType Basic
AuthName "RMB review"
AuthUserFile /home/remarkablcom/public_html/.htpasswd
Require valid-user

<Files .htpasswd>
  Require all denied
</Files>
```

Optional tidy-up, after auth is off: delete `public_html/.htpasswd`. The Kirby `FilesMatch` rule already denies direct access to dotfiles, so leaving the password file in place is harmless but unnecessary.

Do not delete or edit this block, which is generated by cPanel and must stay:

```
# BEGIN cPanel-generated php ini directives, do not edit
...
# END cPanel-generated php ini directives, do not edit
```

If you need to put the site back behind a password, restore the auth block at the top of `.htaccess` (and restore `.htpasswd` if you deleted it). The username is `tutu`.
